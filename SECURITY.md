# Security policy — VOLPAROSSA

VOLPAROSSA is in active development. No repository should be assumed suitable for production security or for protecting sensitive user data unless its own documentation explicitly identifies a supported release and scope.

## Reporting a vulnerability

Please report security issues privately through the affected repository's **Security → Report a vulnerability** feature when available. For issues affecting the shared network core, see [VOLPAROSSA's core security policy](https://github.com/VOLPAROSSA/volparossa/blob/main/SECURITY.md).

Do not disclose exploitation details, credentials, private keys, identifiable network metadata, private user data or confidential logs in public issues. If private reporting is unavailable, open a public issue asking maintainers to establish a private reporting channel, without including sensitive details.

For a report, provide the affected revision, safe reproduction steps, expected behavior and observed behavior, while avoiding private information. We do not publish a fixed response-time guarantee at this stage.

Only test systems, accounts and networks for which you have explicit authorization. Repository-specific SECURITY.md files take precedence over this default.
