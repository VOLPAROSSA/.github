# Questions, support and discussions

VOLPAROSSA is a development project with no supported end-user release. Please
start with the affected repository's README and linked status. Do not rely on a
development build to protect sensitive activity or as your only backup.

| What you need | Where to go |
| --- | --- |
| Understand the project or discuss an idea | [Central Discussions](https://github.com/VOLPAROSSA/volparossa/discussions) and the [FAQ](https://github.com/VOLPAROSSA/volparossa/blob/main/docs/FAQ.md). |
| Report a reproducible bug or propose a bounded change | The affected repository's Issues tab; search existing issues first. |
| Find a first contribution | [Contributor guide](CONTRIBUTING.md); ask about scope before a large change. |
| Report a vulnerability | [Security policy](SECURITY.md); never post exploit details publicly. |
| Report an accessibility barrier | [Accessibility guide](ACCESSIBILITY.md). |
| Discuss research or potential support | Central Discussions for nonconfidential ideas; contact@volparossa.org for a private inquiry. |

Use one central discussion for cross-project questions and link a repository
issue when the work becomes concrete. Avoid posting the same question in multiple
repositories. A discussion is not a commitment to implement an idea.

## Make a question useful

Give a short title, what you were trying to do, the relevant repository/revision,
and what you read or tried. For failures, include the smallest safe reproduction
and environment details. Separate observations from guesses. Summarize or redact
logs: keys, tokens, private files, addresses and browsing history do not belong
in public reports. Reproductions must use systems you are authorized to test.

## Discussion etiquette

Welcome newcomers, explain acronyms and credit sources. Keep disagreement about
the technical claim and follow the [code of conduct](CODE_OF_CONDUCT.md). Share
bounded results with their test conditions, including failures. No promotional
spam, fabricated endorsements or pressure to donate. Mark an answer as helpful
when it resolves your question; summarize the resolution for future readers.

This is a small maintainer-led effort. Replies, review dates, mentoring and feature
delivery are not guaranteed. A focused report is useful even if no immediate fix
is available. Upstream application bugs should follow that project's reporting
guidance after checking whether the issue also occurs without VOLPAROSSA changes.
